# Cure Home — Promo Video Production Guide (playbook for Claude)

*v0.1 · 2026-10-21 · Read this before making or editing any Cure Home video. Source for the first film: `marketing/video/`. Product truth: `docs/01-product/PRODUCT_SPEC.md`. Visual truth: `docs/04-design/DESIGN_GUIDE.md`.*

## 0. How to use this guide

You (Claude) will be asked to make, extend or localise Cure Home videos. Work in this order:
1. Pick the film from the **film suite** (§2) and its audience (§1).
2. Copy its **beat sheet** (§3) and adapt the script; keep claims inside the **claims register** (§6).
3. Build visuals with the **pipeline** that fits (§4): code-rendered UI motion (default), real device capture, live action, 3D renders, AI b-roll.
4. Run the **review checklists** (§8) and the compliance skill before delivering.
5. Deliver to the **spec** (§7), named per the convention, and log the version in §10.

Relevant skills in this workspace: `cure-video-director` (shot lists, VO, captions), `cure-compliance-auditor` (mandatory gate), `cure-content-reviewer` (scoring), `cure-multilingual-translator` (Sinhala/Tamil, native review flagged), `cure-persona-matcher`, `cure-ad-copywriter`. Higgsfield (AI video/image/audio) and Blender (3D, on Dilshan's PC) are connected tools — both cost time or credits; ask before using credits.

### F4 Clinician film — "Home readings you can trust"
1. **Problem (0–15 s):** One clinic BP reading vs white-coat effect; patients forget home readings. Cite guideline-based HBPM, not marketing numbers.
2. **What the hub does (15–45 s):** Guided protocol (rest, posture, 2 readings averaged, morning/evening, HBPM week mode); validated, NMRA-registered cuffs; readings tagged with source, device, time and how the patient was identified.
3. **Data integrity (45–75 s):** Attribution engine; "Who was this?" inbox; duplicates removed; plausibility checks; offline queue.
4. **In your workflow (75–105 s):** HMS consultation screen: 7-day morning/evening averages, adherence, dose-change markers, targets you set appear on the patient's hub.
5. **Safety & privacy (105–130 s):** No diagnosis on the hub; escalation stays with the care team; face data never leaves the home; PDPA-aligned consent.
6. **Close (130–150 s):** "Join the Cure Home pilot at your branch." Contact shown as text.
Use real HMS screenshots from the branch build with demo data only. Never show a real patient's data.

### F3 Social cutdowns
- **6 s bumper:** face circle → greeting → logo. Text: "It knows you. Cure Home."
- **15 s:** recognition → orbit → "Your vitals, gathered around you." → end card.
- **30 s:** recognition → scale → BP → medicine → end card.
Hook within 1.5 s; burned-in captions (sound off); safe zones for Reels/TikTok UI (keep text inside the central 1080×1420 of a 1080×1920 frame).

## 4. Production pipelines

### 4.1 Code-rendered UI motion (default; used for v1)
Folder `marketing/video/`:
- `film.html` — the whole film as one page: tokens, scenes, an **anime.js v4 timeline with `autoplay:false`**, and a `render(t)` function for continuous effects (aurora drift, orbit dots, heartbeat, BLE waves). `window.renderAt(ms)` seeks the timeline and renders that exact frame — deterministic, so frames never drift.
- `render.mjs` — Playwright (Chromium) opens the page at 1920×1080, calls `renderAt` per frame, pipes JPEG screenshots into ffmpeg (H.264, CRF 18, yuv420p, faststart).
- `music.py` — numpy synth score (pads, bell arpeggio, heartbeat motif, chimes on key beats), loudness-normalised with ffmpeg `loudnorm`.

Commands (from `marketing/video/`):
```bash
npm install && npx playwright install chromium  # animejs + renderer (fonts are already in assets/fonts); needs ffmpeg and Python 3 + numpy
node render.mjs x 30 0 '' 1 "3500,20500,42900" # stills at given ms → stills/ (check layout first!)
node render.mjs film_silent.mp4 30            # full render (~8–9 min for 74 s on CPU)
python3 music.py && ffmpeg -i music.wav -af loudnorm=I=-18:TP=-1.5:LRA=11 music_norm.wav
ffmpeg -i film_silent.mp4 -i music_norm.wav -c:v copy -c:a aac -b:a 192k -shortest -movflags +faststart CureHome_F1_EN_16x9_vN.mp4   # §7 naming
```
Editing rules:
- Add a scene: add DOM inside `#stage` or `#screen`, set its initial hidden state in the `utils.set([...], {opacity:0})` list, add timeline entries at absolute ms positions, and keep the global `TOTAL`.
- Always render **stills** at 4–6 key timestamps and look at them before a full render.
- Keep all motion in the timeline or in `render(t)` — never CSS animations or `setTimeout` (they break determinism).
- For 9:16, duplicate `film.html` as `film_vertical.html` with a 1080×1920 stage; reuse the device screen DOM at a different rig scale.
- Optional upgrade path: port scenes to **Remotion** (React components shared with `apps/hub-ui`) once the real UI exists; check the Remotion company licence (free for ≤3-person teams) [U§10], or **HyperFrames** (Apache-2.0).

### 4.2 Real device and UI capture (preferred once the hub runs)
- On the Pi: record the cage/Chromium output with `wf-recorder` at native resolution; disable the camera feed's real faces unless the person has signed a release; use demo household data.
- On the PC: Chrome app window at the panel's CSS size; record with OBS (CQP 16, 60 fps) or Playwright video with an explicit `size`.
- Use the fake-camera fixture (`--use-file-for-fake-video-capture`) with consented footage for repeatable takes.

### 4.3 Live action (F2, F4)
- **Locations:** a real Sri Lankan home (Kandy or Colombo), a Cure branch consultation room.
- **Talent:** real families or actors, with written releases covering health-context use; doctors appearing must be real Cure doctors who consent (follow SLMC guidance on doctors in advertising — no endorsement of products by clinicians beyond describing the workflow).
- **Shot list template:** wide establishing → medium action → insert of screen (shoot screen replacement plates with tracking markers, then composite the rendered UI) → reaction close-up. Shoot 4K 25p, log profile; Dilshan's Canon EOS R6 Mark II is suitable.
- **Screen inserts:** composite the code-rendered UI onto the device screen in post (DaVinci Resolve is installed on the PC) for perfect legibility.

### 4.4 3D product renders (Blender on Dilshan's PC)
Model the hub (10" panel, 8 mm bezel, camera notch with shutter, fabric-back stand) and render: hero ¾ view on a teak sideboard, morning window light; turntable 6 s; exploded view (panel, Pi/CM5 board, camera, speaker) for the clinician/partner films. Use the rendered UI frame as the screen texture.

### 4.5 AI b-roll (Higgsfield) — strict limits
Allowed: atmosphere (rain on a window in Kandy, morning light in a kitchen, tea being poured), abstract textures. Not allowed: AI-generated patients, doctors, readings, or anything presented as a real person or real outcome. Label AI content where required (EU AI Act Art. 50 if shown in the EU) [U§10]. Ask Dilshan before spending credits.

### 4.6 Audio
- VO: native speakers for Sinhala and Tamil (TTS for drafts only). Scripts approved by a native copywriter and a clinician for medical terms.
- Music: the in-repo generator (no licensing risk) or a licensed track; avoid sad/fear cues.
- Loudness: −14 LUFS integrated for social, −16 to −18 LUFS for web/presentations; true peak ≤ −1.5 dBTP.
- Captions: always burned-in for social; SRT/VTT sidecars for YouTube/web in EN, SI, TA.

## 5. Visual language (from the design system)
- Background: deep ink `#04080f → #0d1a2e` with slow aurora (Cure blue `#1089e3`, teal `#14b8a6`, faint lime `#a6ce39`).
- Glass cards: gradient white 15% → 3.5%, 1 px edge at 14–18%, top specular, 16 px blur; status chips with symbols.
- Type: Sora (display, 250–500), Manrope (UI, 600–800), JetBrains Mono (eyebrows), Instrument Serif Italic (one accent phrase per line), Noto Sans Sinhala / Tamil.
- Motion: ease-out-expo for entrances, ease-out-back (1.3–1.6) for cards popping into orbit, 600–1000 ms scene transitions with blur-to-sharp; nothing flashes more than 3 times per second.
- Copy style: short, two-part lines where the second half is the italic serif accent. No exclamation marks. No fear.
- Always show the reading's age and source in UI shots ("Just now · Cure Scale"); never "LIVE".

## 6. Claims register (what we may and may not say)

| Allowed (true by design) | Not allowed |
|---|---|
| "Recognises your family by face" | "Diagnoses", "detects disease", "medical-grade" |
| "Guides you through a blood pressure check" | "Lowers your blood pressure" |
| "Readings are saved and shared with your Cure doctor" | "Your doctor monitors you 24/7" |
| "Face data stays on the device, encrypted" | "100% secure", "unhackable" |
| "Works in Sinhala, Tamil and English" | "Approved by NMRA/FDA" (unless and until true, for the specific item) |
| "Uses validated Bluetooth monitors" (once the kit is fixed) | Accuracy percentages for the hub itself |
| "Concept visualization" (required until launch) | Showing real patient data or identifiable people without releases |

Evidence statements (e.g. home BP monitoring with clinician support improves control) may appear in the clinician film only, with the citation on screen (see `docs/reference/MARKET_REGULATORY_RESEARCH.md` §H3).

## 8. Review checklists

**Visual QA:** no overlapping text; numbers consistent across scenes (e.g. weight 63.0 → 62.4 everywhere); every UI value plausible and inside the claims register; status chips use text + symbol; reading ages shown; Sinhala/Tamil render with correct shaping; nothing flashes > 3 Hz; safe zones respected.
**Copy QA:** one idea per line; no fear; no diagnosis words; all three languages reviewed by native speakers; tagline approved.
**Compliance:** run `cure-compliance-auditor`; "Concept visualization" label present pre-launch; talent/location releases on file; no real PHI.
**Accessibility:** burned-in captions; contrast of captions ≥ 4.5:1; audio-described version for the patient film; VO pace ≤ 140 wpm (≤ 120 for Sinhala/Tamil elderly audience).
**Technical:** duration, resolution, fps, loudness (measure with `ffmpeg -af ebur128`), faststart flag.

## 9. Distribution and measurement
- Cure website product page (F1, F4), Cure patient app "What's new" (F2), Facebook/Instagram/TikTok/YouTube Shorts (F3), WhatsApp broadcast to existing patients' families (F2 9:16), branch waiting-room screens via the HMS video-loop kiosk (F1 muted + captions — the video-loop feature already exists in HMS), clinician briefings (F4).
- KPIs: 3-second view rate, completion rate, pilot sign-up enquiries per branch, clinician pilot enrolments. Feed weekly numbers to `cure-analytics-analyst`.
